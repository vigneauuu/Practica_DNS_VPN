# Piloto exploratorio de 50 dominios

Fecha: 30 de octubre de 2026. Su finalidad es comprobar selección, consultas, controles, almacenamiento y análisis antes de ampliar el experimento. La cantidad de 50 es una decisión de trabajo para esta comprobación, sin representatividad estadística. No sustituye la meta de 2.000 revisados.

## Selección y categorías

Se eligieron por disponibilidad de evidencia documental 39 portales educativos o de investigación, cuatro plataformas de contenido adulto, cuatro sitios de apuestas y tres fabricantes de armas. Esta composición permite comprobar categorías distintas y casos de contenido permitido; no corresponde a cuotas óptimas ni a la distribución de Internet. El predominio educativo impide interpretar una proporción global como rendimiento parental general.

Los portales educativos se identificaron mediante sus páginas institucionales y secciones de estudios o investigación. Para adultos se utilizó la comunicación de la [Comisión Europea del 27 de mayo de 2025](https://digital-strategy.ec.europa.eu/en/news/commission-opens-investigations-safeguard-minors-pornographic-content-under-digital-services-act). Apuestas y armas se documentaron a partir de las funciones o catálogos de sus portales oficiales. No se descargó contenido explícito, no se crearon cuentas ni se hicieron transacciones.

La evidencia por dominio, fecha, categoría propuesta y límites se conserva en `docs/evidencia/piloto-50-revision-documental.json`. Las copias recuperadas de páginas institucionales y su registro de descarga se conservan localmente. La obtención de una página no demuestra que se haya inspeccionado todo el dominio. Una categoría educativa no acredita ausencia de amenazas en todas sus páginas. Algunas direcciones candidatas no pudieron revisarse por errores DNS, TLS, HTTP o tiempo de espera; se dejaron fuera de esta selección, sin inferir su categoría por esos errores.

Esta revisión documental es preliminar. Las 50 filas permanecen `pending`, con su evidencia y la identificación del procedimiento de revisión, sin atribuir a Matías una revisión humana final que todavía no consta. La opción explícita `--include-unreviewed` deja la ejecución marcada como exploratoria. El conjunto principal de 2.000 candidatos y el inventario histórico permanecen sin cambios. No se publicará una estimación de exactitud o falsos positivos a partir de estas etiquetas preliminares.

## Perfiles y calibración

Primero se consultaron cuatro controles técnicos por UDP en seis perfiles, para A y AAAA: 48 observaciones del perfil, con tiempo de espera de 1,5 segundos y sin reintentos. Hubo 28 errores de red; los perfiles Cloudflare de seguridad y familiar y Quad9 sin bloqueo agotaron la espera en sus ocho observaciones cada uno. Estos fallos no se consideran señales de bloqueo.

Se comprobaron después los mismos controles por TCP/53, con tiempo de espera de 2,5 segundos y sin reintentos: se recibieron las 48 respuestas. Como también cambió el tiempo de espera y no se investigó la red completa, esta diferencia no permite atribuir una causa al transporte o al proveedor. La ruta local observada utiliza wlan0; no se habilitó una VPN o proxy ni se modificó el DNS del sistema. DNS convencional por TCP tampoco autentica el servidor remoto.

El piloto compara Cloudflare estándar (1.1.1.1) y familiar (1.1.1.3). Según su [documentación](https://developers.cloudflare.com/1.1.1.1/setup/), el perfil familiar añade protección contra malware y contenido adulto. No se le exige bloquear apuestas o armas por su sola presencia en esas categorías. El control `nudity.testcategory.com` permite comprobar la señal parental; `malware.testcategory.com` comprueba una función adicional de seguridad y no integra el corpus parental. El nombre reservado `.invalid` comprueba el tratamiento de respuestas negativas legítimas.

La calibración TCP devolvió 0.0.0.0 y :: en los controles de categoría para el perfil familiar, mientras el estándar entregó direcciones de resolución. La configuración del piloto incorpora :: como huella empírica de esa calibración, además de la huella IPv4 documentada. No se extiende a otros proveedores. Los mensajes completos se guardan localmente; el extracto revisado está en `docs/evidencia/calibracion-piloto-2026-10-30.json`.

## Ejecución y análisis previsto

Se usan TCP/53, A y AAAA, tres rondas, semilla 20261030, tiempo de espera de 2,5 segundos, intervalo de 0,2 segundos y cero reintentos. Se esperan 600 observaciones del perfil y 1.200 consultas, incluidos controles anterior y posterior para el perfil familiar. Cada observación conserva consulta, respuesta, hora UTC y error. La base nueva mantiene esta ejecución separada de los registros de Windows.

```bash
.venv/bin/python -m pdns_lab.cli run \
  --corpus dataset/piloto-50-2026-10-30.csv \
  --profiles config/piloto-tcp-2026-10-30.json \
  --context config/piloto-contexto-2026-10-30.json \
  --include-unreviewed --rounds 3 --qtypes A,AAAA \
  --timeout 2.5 --retries 0 --interval 0.2 --seed 20261030
```

El análisis informa estados y denominadores por perfil, tipo DNS y categoría. Una respuesta AAAA sin direcciones no se interpreta como bloqueo. Para comparar perfiles se usan únicamente casos interpretables y estables en las tres rondas; se informa cuántos se excluyen. No se mezclan A y AAAA como si fueran dominios independientes para estimar calidad. Acuerdo y Jaccard describen coincidencias; no acreditan acierto. Las mediciones reales y la revisión final de categorías constituyen trabajos distintos.

## Corrección detectada durante el piloto

La regla anterior incluía EDE 18 entre las señales automáticas de bloqueo. El piloto recibió ese código junto con direcciones válidas, en ocasiones acompañado de información sobre un REFUSED de un servidor autoritativo. El RFC 8914, apartados 3 y 4.19, explica que los EDE pueden acompañar respuestas NOERROR y que 18 puede describir un cliente no autorizado. Se retiró ese código de la regla automática. Los códigos 15–17 y las huellas documentadas mantienen su tratamiento. La respuesta completa se conserva para examinar su contexto.

La ejecución de red iniciada con la regla anterior se conserva intacta. `scripts/reclasificar_evidencia.py` genera una base nueva desde sus mensajes, sin repetir la red ni sobrescribir la original. Registra ejecución original, SHA-256 de la base y del clasificador, y cada cambio de estado. El análisis del informe procede de esa base derivada, no de una edición silenciosa de los registros. Las pruebas de regresión comprueban el caso positivo con EDE 18, REFUSED sin evidencia suficiente, conservación de huellas independientes e integridad de la base original.
